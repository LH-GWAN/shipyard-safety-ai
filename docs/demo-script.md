# YardGuard 3분 시연 대본

이 문서의 순서는 `backend/tests/test_smoke_demo.py`와 `scripts/smoke_full_stack.py`가 자동으로 검증하는 경로와 동일하다.
**외부 API 키와 인터넷 연결 없이 전체 시연이 가능하다.**

## 0. 사전 준비 (시연 전에 끝내 둘 것)

```bash
# 터미널 1 - 백엔드
cd backend
../.venv/bin/python -m uvicorn app.main:app --port 8000

# 터미널 2 - 프런트엔드
cd frontend
npm run dev
```

데이터베이스를 깨끗한 상태에서 시작하려면 백엔드를 멈추고 `rm yardguard.db` 후 다시 실행한다.

시연 직전 점검(선택):

```bash
.venv/bin/python scripts/smoke_full_stack.py     # 백엔드 + 프런트엔드 응답 확인
```

## 1. 문제 설명 (25초)

> "조선소에서는 같은 시간, 같은 구역이나 바로 옆 구역에 서로 위험한 작업이 함께 잡히는 일이 생깁니다.
> 작업계획서는 각각 따로 보면 문제가 없어 보이기 때문에, 사람이 한 장씩 넘겨 보는 방식으로는 조합을 놓치기 쉽습니다.
> YardGuard는 여러 작업계획을 **작업 시작 전에 함께 비교해서** 위험한 동시작업과 밀폐공간 안전조치 정보 누락을 찾아 주는 검토 보조 도구입니다."

화면: 대시보드(<http://localhost:3000>). 상단의 제한 문구를 함께 보여준다.
> "결과는 검토 보조정보이고, 최종 확인은 안전관리자가 합니다. 작업허가 승인이나 작업중지 기능은 없습니다."

## 2. 합성 작업계획 확인 (25초)

"작업 등록 → CSV 업로드" 탭에서 `data/work_items.csv`를 선택하고 **검증만 실행**.

- 40행 중 유효 40행, 오류 0행
- "데이터베이스는 변경되지 않았습니다" 안내 확인

> "기본 동작은 검증 전용입니다. 잘못된 행이 섞여 있어도 정상 행의 결과는 그대로 보여주고, 저장은 사용자가 눌러야 합니다."

**유효 행 저장**을 눌러 40건을 등록한다(이미 등록되어 있으면 "기존 ID 덮어쓰기"를 체크).

## 3. 위험 분석 실행 (20초)

"분석 결과" 메뉴 → **규칙 검사 실행**.

- 경보 19건, 전부 등급 높음
- 구역별 시간 배치에서 ⚠ 표시가 붙은 작업 확인

> "판정은 전부 결정론적 규칙 엔진이 합니다. 같은 입력이면 언제나 같은 결과가 나오고, LLM은 이 판정에 관여하지 않습니다."

## 4. 화기작업 충돌 경보 확인 (30초)

경보 목록에서 `R001 · W001, W002` 선택.

- 화기작업(보강재 용접)과 도장작업이 **같은 구역에서 11:00~12:00, 60분 중첩**
- 관련 작업 두 건의 실제 입력값(구역, 시각, 가연물 여부)이 근거로 표시됨

## 5. 밀폐공간 정보 누락 확인 (25초)

규칙 필터에서 `R101` 선택 후 `W026`과 `W027`을 비교한다.

- `W026`: "가스측정 여부가 **입력되지 않았습니다**" (값 미입력 = null)
- `W027`: "가스측정 **미실시로 입력**되었습니다" (false)

> "정보가 없는 것과, 하지 않았다고 입력한 것을 구분해서 다르게 알려 줍니다. 둘 다 확인이 필요하지만 후속 조치가 다르기 때문입니다."

## 6. 경보 근거 확인 (20초)

경보 상세의 '적용 규칙' 영역을 보여준다.

- 규칙명, 버전, 근거 조문(예: 산업안전보건기준에 관한 규칙 제241조제2항제3호)
- 국가법령정보센터 링크와 조문 확인일
- "이 경보는 법 위반 판정이 아닙니다. 현장 적용 전 회사 작업허가 기준으로 검증이 필요합니다."

## 7. 일정 변경안 미리보기 (30초)

다시 `R001 · W001, W002` 경보로 돌아가 이동할 작업 `W002`, 여유시간 30분 → **변경안 미리보기**.

- 변경 전 11:00~14:00 → 변경 후 12:30~15:30 (소요시간 3시간 유지)
- 해소되는 경보 1건, 새로 생기는 경보 0건
- 이 시점까지 원본 데이터는 그대로다

> "규칙으로 계산한 단순 대안입니다. AI 일정 최적화가 아니고, 이동 때문에 새로 생기는 경보도 함께 보여 줍니다."

## 8. 사용자 승인 후 적용 (20초)

**변경안 적용** 클릭.

> "미리보기를 거치지 않으면 적용 자체가 불가능합니다. 서버는 미리보기 토큰을 요구하고, 그 사이에 작업 시간이 바뀌었다면 토큰이 만료되어 409로 거절합니다."

## 9. 재검사 결과 확인 (15초)

- 적용과 동시에 전체 작업을 다시 검사 → 경보 19건 → **18건**
- 작업 목록에서 `W002`의 시간이 12:30~15:30으로 바뀐 것 확인

## 10. 확장 방향 설명 (20초)

"작업 등록 → 자연어 입력" 탭에서 다음 문장을 붙여넣고 **구조화 요청**:

```
2026-03-16T13:00:00+09:00부터 2026-03-16T16:00:00+09:00까지 A_BLOCK_1에서 도장 작업
```

- 모의 어댑터 사용 안내, 필드별 근거·신뢰도 표시
- 값을 확인·수정한 뒤에만 저장

> "지금은 합성 데이터와 자연어 문장으로 동작합니다. 실제 작업허가서를 확보하면 OCR과 서식 매핑을 앞단에 붙여 같은 규칙 엔진으로 검사할 수 있습니다.
> 그 확장 경로와 비식별화 절차는 `docs/work-permit-extension.md`에 정리해 두었습니다."

## 시연 중 자주 나오는 질문

| 질문 | 답변 |
|---|---|
| LLM이 위험을 판단하나요? | 아니요. LLM은 자연어를 입력값으로 바꾸는 데만 쓰고, 판정은 규칙 엔진이 합니다. 등급도 `data/rules.json`에 고정되어 있습니다. |
| API 키가 없으면요? | 등록·CSV·분석·일정 변경 전부 그대로 동작합니다. 자연어 입력만 결정론적 모의 어댑터로 대체되고 화면에 그 사실이 표시됩니다. |
| 실제 작업허가서를 쓰나요? | 아니요. 전부 합성 데이터입니다. 실제 문서 확보 시의 확장 경로만 문서화되어 있습니다. |
| 규칙은 몇 개인가요? | 경보를 만드는 규칙 6개와 입력 검증 규칙 1개입니다. 근거 조문은 국가법령정보센터에서 확인했습니다. |
| 이 결과로 작업을 중지시킬 수 있나요? | 아니요. 승인·중지·설비 제어 기능은 없고, 검토 보조정보만 제공합니다. |
