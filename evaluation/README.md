# 자연어 구조화 평가 (LLM Evaluation)

YardGuard에서 LLM은 **자연어 작업설명을 구조화된 입력값으로 바꾸는 보조 기능**이다.
위험 판정과 경보 등급은 결정론적 규칙 엔진이 결정하므로, 이 평가는 "위험을 잘 맞히는가"가 아니라
**"입력에 명시된 사실만 정확히 뽑아내고, 없는 값을 지어내지 않는가"** 를 측정한다.

## 1. 구성

```
evaluation/
  README.md            이 문서
  cases.json           합성 평가 문장 36개(개인정보·실제 현장정보 없음)
  scoring.py           채점 로직(모의·실제 어댑터 공통)
  evaluate_mock.py     모의 어댑터 평가 (API 키·네트워크 불필요)
  evaluate_remote.py   실제 공급자 평가 (API 키 필요, 명시적 --confirm 필요)
  results/             실행 결과 저장 위치(.gitkeep 외 커밋하지 않음)
```

## 2. 평가 기준

기대값은 어댑터 계약을 그대로 따른다.

- 입력에 **명시된 사실만** 추출한다.
- 명시되지 않은 값은 `null`로 둔다. 상대 날짜("내일 오전")나 모호한 표현을 임의로 확정하지 않는다.
- 표준시간대가 없는 시각은 사용하지 않는다.
- 허용 구역 목록(`data/zones.json`)과 일치하지 않는 위치는 `zone_id=null`로 두고 원문을 근거로 남긴다.
- 안전성·허가 가능 여부·위험등급을 판단하지 않는다.

문장 유형 36개: 정상 화기작업(4), 도장(2), 유기용제(2), 밀폐공간(2), 시간 없음(2), 구역 없음(2),
모호한 날짜(3), 잘못된 구역(2), 종료가 시작보다 이른 문장(1), 안전조치 true(2), false(2), 미언급(2),
가연물 true/false(2), 복수 작업 혼합(2), 표준시간대 없는 시각(1), UTC 시각(1), 시각 3개 이상(1),
작업 종류 미언급(1), 위험 판정 요구(1), 다른 작업 언급(1).

## 3. 평가 지표

| 지표 | 정의 |
|---|---|
| work_type 정확도 | 작업 종류가 기대값과 일치한 문장 비율 |
| zone_id 정확도 | 구역이 기대값과 일치한 문장 비율 |
| 시간 추출 정확도 | start_at과 end_at이 모두 일치한 문장 비율 |
| boolean 필드 정확도 | 안전조치·가연물 4개 필드가 모두 일치한 문장 비율 |
| missing_fields 정확도 | 어댑터가 보고한 미입력 필드 목록이 실제·기대와 일치한 비율 |
| 형식 유효 응답률 | Pydantic 재검증을 통과한 응답 비율 |
| 사용자 수정 필요 비율 | 한 필드라도 수정이 필요한 문장 비율 |
| 임의 추정(환각) 건수 | 기대값이 null인데 값을 채운 필드 수 |

## 4. 실행 방법

```bash
# 모의 어댑터 (API 키 불필요, CI와 동일)
.venv/bin/python evaluation/evaluate_mock.py
.venv/bin/python evaluation/evaluate_mock.py --save     # results/에 JSON 저장

# 실제 공급자 (비용 발생, 명시적 동의 필요)
LLM_PROVIDER=anthropic LLM_API_KEY=... .venv/bin/python evaluation/evaluate_remote.py --confirm --limit 10
```

`evaluate_remote.py`는 키가 없거나 `--confirm`이 없으면 아무 것도 호출하지 않고 종료 코드 2로 끝난다.
`pytest`, `npm test`, GitHub Actions는 모의 어댑터 경로만 실행한다.

## 5. 측정 결과

### 5.1 모의 어댑터 — 측정값 (2026-09-06, 36문장)

| 지표 | 측정값 |
|---|---|
| work_type 정확도 | 88.9% |
| zone_id 정확도 | 97.2% |
| 시간 추출 정확도 | 100.0% |
| boolean 필드 정확도 | 83.3% |
| missing_fields 정확도 | 75.0% |
| 형식 유효 응답률 | 100.0% |
| 사용자 수정 필요 비율 | 27.8% |
| 임의 추정(환각) 건수 | 2건 (C29, C30 - 복수 작업이 섞인 문장에서 하나의 work_type을 선택) |

확인된 모의 어댑터의 한계(설계상 예상된 것):

- 안전조치 표현("가스측정 완료", "환기 미실시", "감시인 배치하지 않음")을 읽지 못하고 항상 `null`을 돌려준다(C21~C24).
- 가연성 물질 사용 여부를 읽지 못한다(C27, C28).
- 사전 정의 키워드만 인식하므로 "밀폐부", "밀폐블록" 같은 변형 표현을 놓친다(C24, C26).
- 한 문장에 여러 작업이 섞이면 키워드 우선순위로 하나를 고르며 모호성으로 처리하지 않는다(C29, C30).
- 여러 구역이 언급되면 목록 순서상 먼저 매칭된 구역을 선택한다(C36).

이 한계는 모의 어댑터가 **키 없이 시연을 가능하게 하는 대체 경로**라는 목적에 따른 것이며,
화면에는 항상 모의 어댑터 사용 사실이 표시된다. 실제 공급자를 설정하면 같은 인터페이스로 대체된다.

### 5.2 실제 공급자 — 미측정 (목표값)

실제 API 키로는 아직 측정하지 않았다. 아래는 **목표값이며 측정 결과가 아니다.**

| 지표 | 목표값 | 상태 |
|---|---|---|
| work_type 정확도 | 95% 이상 | 미측정 |
| zone_id 정확도 | 95% 이상 | 미측정 |
| 시간 추출 정확도 | 95% 이상 | 미측정 |
| boolean 필드 정확도 | 90% 이상 | 미측정 |
| 형식 유효 응답률 | 99% 이상 | 미측정 |
| 임의 추정(환각) 건수 | 0건 | 미측정 |

측정 후에는 이 표를 실제 수치와 측정일자로 교체하고, 목표값과 측정값을 명확히 구분해 적는다.
API 키 없이 실행되는 회귀 테스트는 `backend/tests/test_evaluation_mock.py`가 담당한다.
